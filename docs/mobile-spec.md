# Shoal 手机端（Mobile Access）需求与方案

本文档整理 Shoal（`agent-workbench`）的手机端远程连接与移动交互需求、安全基座、网络通道选型及分阶段验收标准。基础工作台能力见 [v1-spec.md](v1-spec.md)，跨厂商协作机制见 [collab-spec.md](collab-spec.md)，变更与文件面板见 [inspector-spec.md](inspector-spec.md)。

---

## 1. 背景、目标与定位

### 1.1 背景

2026-11-12 讨论中明确了手机端的核心诉求：**不仅要在家里同一 Wi-Fi 下能用手机查看和回复，出门在外（蜂窝网络或异地 Wi-Fi）也要能通过手机随时遥控家里或办公室电脑上的工作台**。

结合对社区开源同类远程方案（`Parallel Code`、`T3 Code`）的架构调研，确立以下基本策略：

- **只复用“电脑向外拨号”的网络原则，不自造中转网络层**：不维护高成本的自建 P2P 打洞/Relay 服务器，不暴露电脑公网端口；复用 Cloudflare Named Tunnel 或 Tailscale Serve 等成熟通道把外部请求送达本机网关。
- **手机端是 IM 对话台，不是缩小的多栏终端**：桌面端的侧栏 + 多分屏宽终端在手机竖屏上操作极其别扭，且缩窄终端尺寸会破坏电脑端正在运行的 ConPTY 布局；手机端主角是结构化对话流、结果卡片、队列状态、快速输入发图以及针对原生弹窗的应急控制条。

### 1.2 定位

定位为**「IM 对话式遥控台 + 终端应急抽屉」**：通过独立鉴权的移动安全网关接入 Shoal 现有会话与协作内核，实现移动端的**进度巡检、排队答复、发图派活、换 Agent 接力、只读 Diff 验收与应急确认**。

## 2. 五条核心设计铁律（Invariants）

1. **铁律 1：电脑本机零打扰**
   - 手机连接默认关闭（`mobileAccess.enabled = false`）。
   - 电脑本机 `127.0.0.1:47800`（Tauri 桌面壳、本机浏览器、CLI `/hook`、`shoal` 协作 `/api/peer/*`）保持免登与既有行为零变化。
2. **铁律 2：双端口物理隔离（防本地反代回环免登漏洞）**
   - 开启手机连接时，在同一 Node 进程内启动独立的**手机安全网关端口**（默认 `47801`）。
   - 由于 `cloudflared` 与 `tailscale serve` 均运行在本机并将外部流量转发到 `127.0.0.1`，若共用端口并按回环 IP 免登会导致外部请求绕过鉴权裸奔；独立 `47801` 端口对**一切请求（含 `127.0.0.1` 来源）100% 强制校验已配对设备凭证**，且物理不挂载 `/hook`、`/api/peer/*`、`POST /api/shutdown`、`POST /api/open`、`GET /api/dirs`（全盘目录浏览）、源码写盘、`git discard` 以及「发起/批准配对、吊销其他设备」等本机管理接口。
3. **铁律 3：绝不缩放桌面 ConPTY 尺寸**
   - 手机窄屏连接**严禁触发 `sessions.resize()`**，防止把电脑端 `120×50` 会话压窄到约 `40` 列导致 CLI TUI 折行错乱与 Windows ConPTY 全屏重绘黑屏闪烁。
   - 手机端新建且桌面未打开面板的后台会话固定采用服务端标准宽屏尺寸（`120×40`）。
4. **铁律 4：按需流式省流量**
   - 手机端 WebSocket 握手后只推结构化状态快照（`Snapshot`）与增量事件，**不主动下发全部会话的历史终端 ANSI 字节流（`replays`）**。
   - 仅当用户在某个任务内展开「终端应急抽屉」时，才按需订阅该单会话的终端输出流。
5. **铁律 5：出门防系统休眠（允许显示器息屏）**
   - 开启手机连接期间，电脑端自动持有 Windows `SetThreadExecutionState(ES_CONTINUOUS | ES_SYSTEM_REQUIRED)` 系统级唤醒锁，防止人离开后电脑自动睡眠断网冻结 Agent；同时**不加 `ES_DISPLAY_REQUIRED`**，让显示器正常黑屏省电。
   - 关闭手机连接或退出工作台应用时自动释放唤醒锁。

## 3. 安全配对与设备鉴权流程（谁能进）

Shoal 驱动的原生 CLI 具备执行本地命令的高权限，手机网关必须实行严格的双端核验配对与单设备独立凭证管理。

### 3.1 电脑扫码 + 本机 6 位确认码双向配对

1. **发起配对（仅限电脑本机）**：仅限在电脑端 `47800` 的「设置 → 手机连接」点击「添加手机」，生成 3 分钟有效的一次性高熵 `pairToken`，展示配对二维码（编码移动网关地址 + `#pair=<pairToken>`，使用 URL hash 避免一次性令牌写入反向代理访问日志）。
2. **手机认领并出码**：手机浏览器扫码打开后自动清掉地址栏 hash，向 `47801` 网关提交配对认领；网关返回并显示 **6 位数字确认码** 与设备简称（如 `iPhone · Safari`、`Android · Chrome`）。
3. **电脑核对批准**：用户在**电脑本机**设置弹窗内核对设备简称并点击批准 / 输入该 6 位确认码。即使二维码或公网链接外泄，缺少电脑前人工核对确认也无法取得访问凭证。
4. **签发隔离长效凭证**：批准后为该设备签发独立的 256-bit 随机令牌：
   - `<stateDir>/mobile.json` 仅存 `SHA-256(token)` 哈希、设备名、`createdAt`、`lastSeenAt` 与最近接入路径，绝不明文落盘原始令牌；
   - 手机端写入 `HttpOnly; SameSite=Lax`（HTTPS 通道下附加 `Secure`）长效 Cookie（90 天滑动续期）；
   - WebSocket 升级严格校验同源 Cookie 与允许的 `Host` / `Origin`（或短期一次性 `wsTicket`）。

### 3.2 防爆破与即时吊销

- 单次配对确认码连续输错 **3 次** 立即作废；配对认领与确认接口按分钟级频率限制。
- 电脑端「设置 → 手机连接」列出全部已配对设备（设备名、配对时间、最近活跃时间与在线状态），支持**单台一键撤销**（立即吊销凭证并主动断开该设备所有活跃 WebSocket）及**全部踢下线**。

## 4. 网络连接通道对比与选型（怎么连上）

用户可通过电脑端「手机遥控」弹窗按需选择连接模式：免账号零配置即可使用的 Cloudflare Quick Tunnel（`trycloudflare.com`），或绑定自有子域名 / Tailscale Serve 的固定 HTTPS 通道；`cloudflared`（如 `cloudflared.exe`）与 OpenSSH 均作为用户本机可选前置组件自动探测。

| 通道方案 | 适用范围 | 手机端前置条件 | 传输隐私与入口形态 | HTTPS 与 PWA 推送 |
| --- | --- | --- | --- | --- |
| **同 Wi-Fi 局域网直连**（内置基础层） | 仅在家 / 办公室同一局域网 | 无需装 App，手机浏览器直接扫码；服务端过滤 WSL / Hyper-V 虚拟网卡选真实局域网 IP，并在应用层校验私网 / CGNAT 网段 | 局域网直连，`<5ms` 极低延迟，不经过外部节点 | 仅 HTTP（不直接满足浏览器 Web Push 安全上下文） |
| **Cloudflare Quick Tunnel**（免账号零配置） | 临时出门快速连接 | **无需 Cloudflare 账号或自有域名**，只需本机装有 `cloudflared`，每次开启生成随机 `https://*.trycloudflare.com` 地址 | 电脑 `cloudflared` 主动外拨 `127.0.0.1:47801`；适合快速体验，重启后地址更新需重新扫码 | 原生合法 HTTPS，零域名成本 |
| **Cloudflare Named Tunnel**（固定子域名首选） | 在家 + 出门外网长期可用 | **免装 VPN App，不抢占手机常驻代理 VPN 槽位**，浏览器 / PWA 直接固定访问自有子域名 | 电脑 `cloudflared` 主动外拨 `127.0.0.1:47801`；可叠加 Cloudflare Access（Zero Trust 邮箱门禁）+ Shoal 设备配对双保险 | **原生合法 HTTPS 证书**，适合长期「添加到主屏幕」；设置页托管启停并探活 |
| **Tailscale / Tailscale Serve**（端到端加密备选） | 在家 + 出门外网 | 手机与电脑均需安装并开启 Tailscale VPN（注意 Android 同时只能开一个 VPN，需确认是否与常用代理软件冲突） | WireGuard 端到端加密，不暴露公网域名 | 启用 Tailscale Serve 后可提供 `.ts.net` HTTPS 地址；网关天然兼容手动填入外部 HTTPS 入口 |

## 5. 手机端界面与交互范围（手机上做什么）

复用现有 React + Vite 前端构建产物，当客户端访问移动安全网关端口（`47801`）时自动渲染专为竖屏单手操作设计的移动视图；提供 `manifest.webmanifest` 支持「添加到主屏幕」以 PWA 全屏运行，全面适配 `100dvh` 动态视口（防止手机输入法弹起顶飞底部栏）与 `env(safe-area-inset-*)` 安全区，并继承隐私模式（隐藏真实项目路径与敏感标题）。

### 5.1 首页：待办置顶与活跃总览

- **顶部状态栏**：当前连接状态与链路延迟胶囊（局域网直连 / 隧道在线 / 重连中）、Claude / Codex / `agy` 三端订阅额度圆环概览、「+ 新建任务」按钮。
- **「需要你 & 待验收」置顶卡片区**：将处于 `needs_you`（琥珀色高亮，显式区分启动确认弹窗与中途提问）与 `review`（待验收）状态的任务置顶，直接展示项目名、任务标题、等待时长与最新摘要。
- **项目与运行中任务列表**：项目内按 `lastActiveAt` 降序排列，运行中的任务直接显示 `SessionActivity.summary` 单行实时进展（如 `正在编辑 server/http.ts · 6 步 · 2m`），已退出的旧任务默认折叠。

### 5.2 任务详情页：结构化 IM 对话流 + 底部操控坞（核心主战场）

- **结构化对话流**：基于 `server/transcript.ts` 扩展只读对话流接口（兼容 Claude / Codex / `agy`），渲染用户提问气泡、Agent Markdown 回复、交接卡（`handoff`）与转发卡（`forward`）；连续的工具调用（`tool`）自动折叠为单行「执行了 N 步工具操作 ▸」（点击按需展开明细）；会话工作中在对话流底部实时呈现 `SessionActivity` 白盒进度卡（当前阶段、思考片段与读写文件计数）。
- **底部操控坞与安全排队投递**：多行自适应输入框（原生兼容手机系统语音输入法）+ 相册 / 拍照传图按钮（复用 `POST /api/attachments` 20 MB 图片上传粘贴通道），后端统一走既有 `pasteIntoTask` 4 道 PTY 安全护栏投递（目标正在忙时显示「排队发送 (N)」，目标会话已退出时自动续接后投递）。
- **验收与跨 Agent 调度**：任务处于待验收状态时，在输入框上方展示紧凑快捷条 **`[ 变更 Diff (N) ]` `[ 转发 ]` `[ ✓ 通过 ]`**；右上角「⋯」菜单提供**「换 agent」**（某家额度耗尽时出门一键切另一家 CLI 生成交接卡片继续干）、**「新会话继续」**（带当前结论开新会话）与**「归档」**；转发弹窗同样支持勾选「对方本轮完成后，自动把结果传回源任务」。

### 5.3 终端应急抽屉（`>_` 原生 TUI 弹窗与打断兜底）

- 当会话处于 `startupBlocked`（如 Claude 目录信任提示、Codex `Hooks need review`）、停在 CLI 原生交互选择框或用户主动点击标题栏 `>_` 按钮时，底部滑出终端应急抽屉：
  - 上半区为**只读终端视口**：按桌面端当前行列数渲染最近屏幕缓冲，支持横向滑动与双指缩放查看，**绝不发送 `resize`**；
  - 下半区为**触屏快捷按键栏**：提供 `y`、`n`、`Enter`、`Esc`、`↑`、`↓`、`Tab`、`1`、`2`、`3`、`Ctrl+C` 等高频键位，专门处理权限审批、菜单选择与紧急中断。

### 5.4 只读变更检视抽屉（Diff Sheet）

- 复用 Inspector 的 `git` 与 `diff` 只读接口，以单列窄屏卡片展示当前项目改动文件列表（`M / A / D / R / ?`）与单文件上下行内 Diff，方便出门验收前核对关键代码改动。

### 5.5 快速新建任务抽屉（New Task Sheet）

- 从电脑端已登记的项目中选择目标项目 → 选择 Agent（含 `agy` 默认模型档位）→ 填写需求提示词直接派活（遵循服务端 `120×40` 默认宽屏尺寸启动）。

### 5.6 安全裁剪边界（手机端明确不开放）

为收口远程攻击面与误操作风险，手机网关接口层**严格禁止并移除**以下能力：

- 不开放全盘磁盘目录浏览（`GET /api/dirs`）及新增/修改本机项目根目录；
- 不开放源码在线编辑保存（`PUT /api/file`）与 `git discard` 放弃改动（防止窄屏误触丢代码）；
- 不开放关停工作台进程（`POST /api/shutdown`）与本机编辑器/资源管理器调起（`POST /api/open`）；
- 不开放生成新配对二维码、批准其他设备或吊销其他已配对设备的权限。

## 6. 手机锁屏提醒与推送通知（怎么知道 Agent 停下了）

### 6.1 触发与静默策略

- **触发条件**：任意活跃任务由运行中转入 `needs_you`、`review`（待验收）或触发 `limit`（额度用完）。
- **防刷屏机制**：单任务状态抖动去重防抖；支持在设置中开启「电脑本机近期活跃操作时静默通知」，避免坐在电脑前时手机重复响铃。

### 6.2 双通道设计

1. **轻量 Webhook 通道（国内网络环境最稳、不依赖 Google FCM）**：支持填写飞书自定义机器人 Webhook、Bark（iOS）URL 或通用 JSON Webhook，由电脑服务端直接发起出站 HTTPS POST。
2. **PWA 标准 Web Push（VAPID）**：在 HTTPS 通道访问并添加到手机主屏幕后，电脑服务端通过本机生成的 VAPID 密钥对直推系统级锁屏通知，点击通知直接拉起对应任务详情页。

### 6.3 隐私脱敏铁律

任何经由外部推送服务中转的通知载荷**只允许包含：项目名、任务标题与等待状态类型**，严禁携带代码片段、本地文件系统路径、终端输出或回复正文。

## 8. 分阶段实施路线图与验收门禁

### M-Mobile 1：安全基座 + 手机对话/应急终端视图 + 同 Wi-Fi 直连 + 防休眠

- **交付范围**：
  - 双端口安全网关（`47801`）、扫码 + 本机 6 位确认码配对、`mobile.json` 哈希存储、单设备撤销与全部踢下线；
  - 移动首页（待办置顶 + 实时进度）、任务 IM 对话详情页（含工具步骤折叠、排队发送、相册发图、换 Agent、转发与通过）、只读 Diff 抽屉、终端应急抽屉（触屏快捷键）与快速新建任务；
  - Windows 防休眠锁。
- **验收门禁（Playwright 手机视口 e2e + 单元/集成测试）**：
  1. 未登录、过期 Cookie、篡改凭证及伪造 `Host` / `X-Forwarded-*` 回环反代头访问 `47801` 一律返回 `401`/`403`；危险接口（`POST /api/shutdown`、`PUT /api/file`、`GET /api/dirs` 等）在 `47801` 不可达；
  2. 配对完整闭环与防爆破（错 3 次作废），电脑端撤销某台手机后该设备活跃 WebSocket 在 1 秒内断开；
  3. **零缩放硬性校验**：手机视口（如 `390×844`）打开任务详情与终端应急抽屉全程，服务端监听桌面会话 `resize` 计数严格为 `0`；
  4. 忙时排队投递、图片上传粘贴与只读 Diff 展示在移动端完整跑通。

### M-Mobile 2：出门远程通道集成与链路透明

- **交付范围**：
  - 电脑端设置页托管 `cloudflared` Named Tunnel 启停与状态探活，同时保留外部 HTTPS 地址（如 Tailscale Serve）手动填入入口；
  - 手机顶栏展示当前连接路径与实时往返延迟，支持本地局域网地址与远程 HTTPS 入口无缝复用已配对设备态。
- **验收门禁**：
  - 断开电脑同局域网 Wi-Fi，使用手机蜂窝网络完成从列表查看、发图/文字派活、应急快捷键确认到 Diff 验收的真机全链路验证。

### M-Mobile 3：锁屏消息推送

- **交付范围**：
  - 飞书 / Bark / 自定义 Webhook 与 PWA VAPID Web Push 双通道；
  - 状态防抖、本机活跃静默开关与通知体脱敏单测校验。
- **验收门禁**：
  - 模拟任务转入 `needs_you` / `review` / `limit` 触发实机或模拟订阅推送，校验载荷不含源码、路径与正文且点击可直达目标任务页。

## 9. 开源架构与默认配置约定

1. **客户端与通道分层**：桌面默认不开启手机网关（`enabled = false`）；移动视图面向 Android / iOS 浏览器与 PWA 全屏模式（`100dvh` 动态视口与底部操控坞）；公网出站默认提供免账号 Quick Tunnel（`tunnelMode = 'quick'`），并完整支持用户自带域名 + Named Tunnel，通过双端口物理隔离、零回环免登、`Host`/`Origin`/`X-Shoal-Mobile: 1` 校验、`#pair=` 一次性令牌 + 本机 6 位确认码、`SHA-256` 凭证哈希、环境变量 `TUNNEL_TOKEN` 注入与可选 Cloudflare Access `RS256` JWT 实现纵深安全。
2. **手机端只读安全裁剪边界**：完全禁止全盘目录浏览（`GET /api/dirs`）、项目增删、在线源码写盘（`PUT /api/projects/:id/file`）、放弃 Git 改动（`POST /api/projects/:id/discard`）、关停服务（`POST /api/shutdown`）、调起本机编辑器（`POST /api/open`）、`/hook`、`/api/peer/*` 与配对/吊销管理接口，并对返回给移动端的本地绝对路径统一脱敏。
3. **多生态锁屏通知与防 SSRF**：统一通过桌面端出站推送飞书（支持 HMAC-SHA256 签名）、Discord、Slack、Telegram 或通用公网 HTTPS Webhook（带 `X-Shoal-Signature` 签名与内网/DNS 重绑定拦截），支持状态防抖、本机活跃静默与严格载荷脱敏。
4. **开源文档与自配导引**：具体安装与分流排障操作见 [mobile-guide.md](mobile-guide.md)。
